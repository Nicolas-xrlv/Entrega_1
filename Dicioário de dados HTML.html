Dicionário de Dados

Distribuidora de Bebidas

1. Modelo conceitual

O modelo representa as principais informações necessárias para apoiar as operações de cadastro, vendas, compras e controle de estoque de uma distribuidora de bebidas.

Entidade Relaciona-se com Cardinalidade Descrição
CategoriaProduto1:NUma categoria pode possuir vários produtos, enquanto cada produto pertence a uma categoria.
ClienteVenda1:NUm cliente pode realizar várias vendas, enquanto cada venda pertence a um cliente.
FuncionárioVenda1:NUm funcionário pode registrar várias vendas, enquanto cada venda é registrada por um funcionário.
VendaItem_Venda1:NUma venda pode possuir vários itens, enquanto cada item pertence a uma venda.
ProdutoItem_Venda1:NUm produto pode aparecer em vários itens de venda.
FornecedorCompra1:NUm fornecedor pode estar relacionado a várias compras.
CompraItem_Compra1:NUma compra pode possuir vários itens.
ProdutoItem_Compra1:NUm produto pode aparecer em várias compras.
ProdutoEstoque1:1Cada produto possui um registro de estoque para controlar sua quantidade disponível.
FornecedorProdutoN:NUm fornecedor pode fornecer vários produtos e um produto pode ser fornecido por diferentes fornecedores.

Cliente representa as pessoas ou empresas que realizam compras na distribuidora. Produto representa as bebidas e demais produtos comercializados. Categoria organiza os produtos em categorias. Fornecedor representa as empresas responsáveis pelo fornecimento. Funcionário representa os funcionários responsáveis pelas atividades da distribuidora. Venda registra as vendas realizadas. Item_Venda detalha os produtos e quantidades de cada venda. Compra registra as compras realizadas junto aos fornecedores. Item_Compra detalha os produtos e quantidades adquiridos. Estoque controla a quantidade disponível de cada produto.

A notação formal foi adaptada do padrão apresentado no documento de referência. Ela permite indicar identificadores, obrigatoriedade e opcionalidade dos atributos.

Tipos físicos: os tipos indicados neste documento são propostas preliminares para representar os atributos em um SGBD. Eles não substituem a definição do modelo lógico e físico, que deverá ser feita posteriormente.

Leitura: @ID_CLIENTE é o identificador único. Os atributos conectados por + são considerados obrigatórios na definição preliminar. Os atributos entre ( ) são opcionais.

STATUSvarchar(10)SimSituação do cadastro, permitindo indicar Ativo ou Inativo.

PRODUTO = @ID_PRODUTO + NOME_PRODUTO + (DESCRICAO) + ID_CATEGORIA + PRECO_VENDA + ATIVO

Leitura: @ID_PRODUTO identifica o produto. ID_CATEGORIA relaciona o produto à entidade CATEGORIA. DESCRICAO é opcional.

ESTOQUE

ESTOQUE = @ID_ESTOQUE + ID_PRODUTO + QUANTIDADE_ATUAL + (LOCALIZACAO) + DATA_ATUALIZACAO

Leitura: @ID_ESTOQUE identifica o registro de estoque. ID_PRODUTO referencia o produto controlado. A localização é opcional.

AtributoTipo físicoObrigatórioSignificado e relevância
ID_ESTOQUEintegerSim (PK)Identificador único do registro de estoque.
ID_PRODUTOintegerSim (FK)Produto relacionado ao registro de estoque.
QUANTIDADE_ATUALintegerSimQuantidade disponível atualmente no estoque; não pode ser negativa.
LOCALIZACAOvarchar(100)NãoLocal onde o produto está armazenado.
DATA_ATUALIZACAOdateSimData da última atualização do estoque.
Regra do Estoque. Cada produto possui um registro de estoque para controlar sua quantidade disponível. Quando uma compra é registrada, a quantidade do produto pode ser acrescentada ao estoque. Quando uma venda é realizada, a quantidade correspondente deve ser retirada do estoque. A relação é Produto 1:1 Estoque.

Restrições e políticas do modelo

  • Cada entidade possui um identificador único, utilizado como chave primária.
  • As chaves estrangeiras devem referenciar registros existentes.
  • Uma venda deve possuir pelo menos um item.
  • Uma compra deve possuir pelo menos um item.
  • A quantidade dos produtos vendidos ou comprados deve ser maior que zero.
  • Preços e valores monetários não podem ser negativos.
  • Uma venda deve reduzir a quantidade disponível do produto no estoque.
  • Uma compra deve aumentar a quantidade disponível do produto no estoque.
  • Um produto deve estar vinculado a uma categoria.
  • Um produto pode ser fornecido por um ou mais fornecedores.
  • Clientes, fornecedores, funcionários, produtos e categorias podem possuir status para indicar se estão ativos ou inativos.
  • Dados pessoais e cadastrais devem ser armazenados somente quando necessários para as operações da distribuidora.
  • Os exemplos utilizados no projeto devem ser fictícios e não devem representar dados reais de clientes, funcionários ou fornecedores.

5. Observações para a etapa lógica

Fornecedor — Produto (N:N). O relacionamento permanece N:N no modelo conceitual, conforme o projeto. Na transformação para o modelo lógico, ele poderá ser resolvido por uma entidade associativa caso seja necessário armazenar informações específicas desse relacionamento.
Produto — Estoque (1:1). Para preservar a cardinalidade 1:1 no modelo lógico, o identificador do produto deverá ser tratado de modo a não permitir múltiplos registros de estoque para o mesmo produto.
Tipos físicos preliminares. Os tipos como integer, varchar, decimal, date, text e boolean foram utilizados apenas para aproximar o padrão do documento de referência. A escolha definitiva do SGBD e dos tipos físicos pertence à etapa de modelagem lógica/física.

Este dicionário utiliza as entidades e atributos definidos no modelo conceitual da Distribuidora de Bebidas. Não foram incluídos dados reais de pessoas ou empresas.
